# Plan: Run an Android project on the pane's device

Goal: pick a Flutter or native Android (Gradle/Kotlin) project folder, pick its flavor and build
type, and run it on the device selected in Mobile Pane, with build/run output, Stop and (Flutter)
hot reload / hot restart. Android Studio is no longer needed for this.

Out of scope (v1): breakpoint debugger, iOS (Run is disabled while an iOS Simulator is selected),
release signing (release variants without a signing config are not listed), multi-dimension
Flutter flavors beyond passing the combined name.

## Design decisions

1. **Gradle variants come from Gradle itself, via an init script, cached.** Parsing
   `productFlavors` misses flavor dimensions, convention plugins and computed applicationIds. The init
   script below uses AGP's `androidComponents` API and prints module, variant, flavor, build type,
   final applicationId (flavor suffixes applied) and the install task, only for variants that have
   an install task. Verified on a copy of `elhp`: 4 to 8 s, all 6 debug variants with correct ids
   (`com.dsn.elhp.dev.ai`, task `:app:installDev-aiDebug`), release correctly absent.
   `./gradlew tasks --all` was the alternative: same cost, but gives no applicationId and needs
   text parsing. Cache key: a hash of the path + mtime of the build files (see piece A); a
   **Refresh** button forces a new run.
2. **Flutter flavors come from a static parse plus `.vscode/launch.json`.** Flutter projects often
   have no `android/gradlew` (it is generated by the flutter tool), so Gradle can't be asked.
   Flutter flavors are one dimension in practice; a brace-matching parse of `productFlavors { }` in
   `android/app/build.gradle(.kts)` got every project above right (Groovy `dev {`, KTS
   `create("dev")`, hyphens). launch.json configurations become **presets** (flavor + mode + extra
   args such as `--dart-define=APP_FLAVOR=dev`), because two of the projects don't work without
   their dart-define. A preset is preselected when one exists.
3. **Flutter runs as `flutter run --machine` with buttons, not in a Ghostex terminal.** The pane
   gets structured events (progress, app started/stopped, logs), real phase/status, and Hot reload /
   Hot restart / Stop buttons sending JSON-RPC (`app.restart`, `app.stop`) on stdin. A Ghostex
   terminal (`ghostex terminal` / `run-in-terminal`) would need the `ghostex` CLI and a project id
   from inside the extension server (not in its env today), and the pane could not show state or
   offer buttons.
4. **Flutter SDK = the fvm-pinned SDK binary, called directly.** Pinned version from `.fvmrc`
   (`flutter`) or legacy `.fvm/fvm_config.json` (`flutterSdkVersion`); binary
   `${FVM_CACHE_PATH:-~/fvm/versions}/<version>/bin/flutter`. Same SDK that `fvm flutter` would use,
   but no fvm prompt can hang a process without a TTY, and broken `.fvm/flutter_sdk` symlinks don't
   matter. No pin: `~/fvm/default/bin/flutter`, then `flutter` on PATH. Pinned but not installed:
   see open question 1 (default: use `~/fvm/default` and log a warning line).
5. **Kotlin: `sh gradlew <installTask>` with `ANDROID_SERIAL=<serial>`, then force-stop + launch,
   then the app's logcat.** `sh` because `gradlew` may lack the exec bit. `ANDROID_SERIAL` makes the
   install task target only the pane's device. Launch with `am force-stop` then
   `monkey -p <appId> -c android.intent.category.LAUNCHER 1` (same as the existing agent `launch`
   action), so a re-run restarts the app like Android Studio. Run output = `adb logcat --pid=<pid>`.
6. **Explicit toolchain env.** Every spawned command gets `ANDROID_HOME` (from `androidSdk()`),
   `JAVA_HOME` (resolved, see piece A) and a PATH with platform-tools, `$JAVA_HOME/bin`, the flutter
   bin dir, `/opt/homebrew/bin`, `/usr/local/bin`. No login shell.
7. **One run job at a time, polled.** A new Run stops the old one. Output is a ring buffer of the
   last 5000 lines with sequence numbers; the UI polls `GET /run/state?since=<seq>` every 500 ms
   while the Run panel is open or a job is active (the Devices panel already polls the same way).
8. **Folder picking = typed path + recents.** The view is a web page: it can't get an absolute path
   from a native folder dialog. A text input with `~` expansion, a `<datalist>` of the last 10
   projects (stored server-side in `$DATA_DIR/run-projects.json` with the last selection per
   project), and `GHOSTEX_PROJECT_PATH` (in the server env) offered when it is an Android/Flutter
   project. Picking `<flutter project>/android` is treated as the Flutter project.
9. **Security.** Anything that spawns a process is a POST (the server already refuses non-GET from
   other origins). Commands are spawned with argument arrays, never a shell string. The install task,
   flavor and serial must match what the server itself listed.

### A. Project detection, variants, toolchain, recents

- **Goal:** know what a folder is, what can be run, and with which tools.
- **Creates:** `src/project.mjs`, `src/mobile-pane-variants.gradle`. Changes nothing else.
- **Exposes** (`src/project.mjs`):
  - `detectProject(path) → Promise<Project>`. Expand a leading `~`, `path.resolve`, `fs.realpath`,
    must be a directory. Flutter: `pubspec.yaml` and an `android/` folder (else throw
    `"Flutter project has no android/ folder"`). If the folder is `<x>/android` and `<x>/pubspec.yaml`
    exists, return the Flutter project `<x>`. Gradle: `settings.gradle` or `settings.gradle.kts`.
    Otherwise throw `"Not a Flutter or Android Gradle project: <path>"`. `fvmVersion` from `.fvmrc`
    (`{"flutter": "3.32.0"}`) or `.fvm/fvm_config.json` (`{"flutterSdkVersion": "3.13.0"}`), else null.
  - `listVariants(project, dataDir, { refresh = false } = {}) → Promise<Variants>`.
    - Gradle: run `sh gradlew -q --console=plain --no-configuration-cache --init-script
      <dist>/mobile-pane-variants.gradle mobilePaneVariants` (cwd = project path, env from
      `toolchain()`, timeout 5 min). Keep lines starting `MOBILE_PANE_VARIANT\t`, split on `\t`:
      `[_, module, name, flavor, buildType, applicationId, installTask]`. No line → throw with the last
      30 lines of output. No `gradlew` → throw `"No gradlew in <path>"`.
    - Cache in `<dataDir>/run-variants.json`: `{ [path]: { fingerprint, variants } }`. Fingerprint =
      sha1 of the sorted `relative path:mtimeMs` of every `settings.gradle*`, `build.gradle*`,
      `gradle.properties`, `gradle/*.toml` and everything under `buildSrc/` and `build-logic/`, to a
      depth of 3, skipping `build`, `.gradle`, `.git`, `node_modules`. Same fingerprint and no
      `refresh` → cached answer, no Gradle run.
    - Flutter (no cache, it is a fast file read): `flavors = parseFlavors(android/app/build.gradle(.kts))`,
      `targets` = `lib/main*.dart`, `presets = parseLaunchJson(.vscode/launch.json)`.
  - `parseFlavors(src) → string[]`: strip `/* */` and `//` comments, find `productFlavors {`,
    brace-match its block, and return the names of its direct children:
    `create|register|maybeCreate|getByName("name") {` or a bare/quoted `name {`. A working version
    is below.
  - `parseLaunchJson(src) → Preset[]`: strip comments and trailing commas, `JSON.parse`; for each
    configuration with `type: "dart"`, join `toolArgs` and `args`; take `--flavor x` / `--flavor=x`,
    `-t x` / `--target x` / `--target=x` (or `program`) out; `mode` from `flutterMode` (default
    `debug`); the rest stays in `args`. Bad JSON → `[]`.
  - `toolchain(project) → Promise<{ env, flutter, notes }>`:
    - `JAVA_HOME`, first that exists: `process.env.JAVA_HOME`;
      `/Applications/Android Studio.app/Contents/jbr/Contents/Home` (and under `~/Applications`);
      the output of `/usr/libexec/java_home` when it exits 0;
      `/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home`, then `openjdk@21`, then
      `openjdk`; then `/Library/Java/JavaVirtualMachines/*/Contents/Home`. None → throw
      `"No Java found for Gradle. Install a JDK (brew install openjdk@17) or set JAVA_HOME."`
    - `ANDROID_HOME` = `androidSdk().sdk` (import from `./android.mjs`); none → throw.
    - `flutter` (Flutter projects only, else null): see decision 4. When the pinned version is
      missing, push to `notes`: `"Flutter <v> pinned in .fvmrc is not installed; using <fallback>.
      Run fvm install <v> to use it."`
    - `env` = `{ ...process.env, ANDROID_HOME, JAVA_HOME, PATH }` with PATH as in decision 6.
  - `recentProjects(dataDir) → Promise<[{ path, name, type, last, usedAt }]>` (newest first) and
    `rememberProject(dataDir, project, last?) → Promise<void>` (upsert into `<dataDir>/run-projects.json`,
    keep `last` when not given, cap at 10).
- **`src/mobile-pane-variants.gradle`** (verified on `elhp`, copy exactly):

  ```groovy
  // Mobile Pane: prints one tab-separated line per installable variant of every Android app module:
  // MOBILE_PANE_VARIANT <module path> <variant> <flavor> <build type> <applicationId> <install task>
  // Needs AGP 7+ (androidComponents). Run with --no-configuration-cache.
  allprojects { p ->
    p.plugins.withId('com.android.application') {
      def variants = []
      p.androidComponents.onVariants(p.androidComponents.selector().all()) { v -> variants << v }
      def lines = []
      p.gradle.projectsEvaluated {
        variants.each { v ->
          def task = 'install' + v.name.substring(0, 1).toUpperCase() + v.name.substring(1)
          if (p.tasks.names.contains(task)) lines << [p.path, v.name, v.flavorName ?: '', v.buildType ?: '', v.applicationId, "${p.path == ':' ? '' : p.path}:${task}"]
        }
      }
      p.tasks.register('mobilePaneVariants') {
        doLast { lines.each { l -> println(['MOBILE_PANE_VARIANT', l[0], l[1], l[2], l[3], l[4].get(), l[5]].join('\t')) } }
      }
    }
  }
  ```

- **`parseFlavors` reference** (got all six projects above right):

  ```js
  export function parseFlavors(src) {
    src = src.replace(/\/\*[\s\S]*?\*\//g, "").replace(/(^|[^:"])\/\/.*$/gm, "$1");
    const m = /\bproductFlavors\s*\{/.exec(src);
    if (!m) return [];
    let depth = 1, top = "";
    for (let i = m.index + m[0].length; i < src.length && depth; i++) {
      const c = src[i];
      if (c === "{") depth++;
      else if (c === "}") depth--;
      if (depth === 1 && c !== "}") top += c;
      else if (depth === 2 && c === "{") top += "{";
    }
    const re = /(?:(?:create|register|maybeCreate|getByName)\s*\(\s*["']([^"']+)["']\s*\)|^\s*["']?([A-Za-z_][\w-]*)["']?)\s*\{/gm;
    return [...top.matchAll(re)].map(([, a, b]) => a ?? b);
  }
  ```

- **Check:**
  - `node src/project.mjs --self-check`: `console.assert`s (exit 1 on failure) for `parseFlavors` on
    inline snippets (Groovy bare names, KTS `create("dev-ai")`, `register`, a commented-out flavor,
    no block → `[]`) and `parseLaunchJson` on a JSONC snippet with comments, trailing comma,
    `toolArgs: ["--flavor","fruitsDev","--dart-define=APP_FLAVOR=fruitsDev"]`.
  - `node src/project.mjs <path>` prints `{ project, variants, toolchain: { flutter, notes, JAVA_HOME } }`.
    For Gradle, run it on a **copy** (`rsync -a --exclude build --exclude .gradle <project>/ <scratch>/`),
    never the user's folder. Expected against the table above: `elhp` copy → 6 variants, ids
    `com.dsn.elhp.{dev,dev.ai,pwp,pwp.ai,swa,swa.ai}`, `:app:installDev-aiDebug`, no release;
    `uchi-fruits-mobile` → flavors `fruitsDev, fruitsProd`, 2 presets with the dart-define;
    `egrading` → flavors `[]`, `fvmVersion` 3.13.0, flutter = `~/fvm/versions/3.13.0/bin/flutter`;
    `employee_recognition_mobile` → a note that 3.32.0 is not installed. Second run on the `elhp`
    copy returns at once (cache); touching its `app/build.gradle.kts` makes Gradle run again.
- **Depends on:** nothing.

### B. Runner: build, install, launch, logs, stop, hot reload

- **Goal:** run one job at a time and expose its state and output.
- **Creates:** `src/runner.mjs`. Changes nothing else.
- **Consumes:** from A `detectProject`, `listVariants`, `toolchain`, `rememberProject`; from
  `./android.mjs` `androidSdk`, `listDevices`, `run`.
- **Exposes:**
  - `startRun(body, dataDir) → Promise<{ ok: true, job }>`. `body` =
    `{ path, serial, gradle?: { installTask }, flutter?: { flavor, mode, target, args } }`.
    Validate: `serial` is in `listDevices()` with state `device`; project via `detectProject`;
    gradle `installTask` is in `listVariants(...).variants` (cached); flutter `flavor` is in `flavors`
    (or null when the list is empty), `mode` in `modes`, `target` null or in `targets`, `args` an
    array of strings. Stop the current job first. Call `rememberProject(dataDir, project, selection)`.
  - `stopRun() → Promise<void>`, `reloadRun(full) → Promise<void>` (throws unless `canReload`),
    `runState(since) → RunState` (shape above).
- **Behaviour:**
  - Log helper: split stdout/stderr into lines (`node:readline`), strip ANSI (`/\x1b\[[0-9;]*[A-Za-z]/g`),
    push `{ seq, stream, text }`, keep the last 5000. Phase changes and notes from `toolchain()` go in
    as `info` lines. Spawn with `detached: true` so Stop can `process.kill(-pid, "SIGTERM")` the whole
    group (SIGKILL after 5 s).
  - Gradle: phase `building`: `sh gradlew --console=plain <installTask>` (cwd project, env +
    `ANDROID_SERIAL=<serial>`). Exit ≠ 0 → `failed`, error `"Gradle failed (exit N)"`. Then
    `launching`: `adb -s <serial> shell am force-stop <appId>`, then
    `adb -s <serial> shell monkey -p <appId> -c android.intent.category.LAUNCHER 1`; output without
    `Events injected: 1` → `failed` `"<appId> has no launcher activity"`. Then `running`: poll
    `adb -s <serial> shell pidof <appId>` every 500 ms up to 10 s, then spawn
    `adb -s <serial> logcat -v time --pid=<pid>` into the log. Logcat ends → info line
    `"App process ended"`, phase `stopped`. Stop while running → `am force-stop <appId>` too.
  - Flutter: spawn `<toolchain.flutter> run --machine -d <serial> [--flavor f] --<mode>
    [-t target] ...args` (cwd project, stdin piped). Phase `building` at start. Each stdout line
    that starts with `[{` is a JSON array; handle:
    `app.start` (keep `params.appId`, phase `launching`), `app.started` (phase `running`),
    `app.progress` (`params.message` as info when present), `app.log` (`params.log`, stream `err` when
    `params.error`), `daemon.logMessage` (`params.message`, `err` when `level` is `error`),
    `app.stop` (phase `stopped`, or `failed` with `params.error`), and responses `{ id, result | error }`
    for pending requests. Other lines go in as plain `out` lines. Process exit before `app.stop` →
    `failed` with the exit code.
    Requests: write `[{"id":N,"method":"app.restart","params":{"appId":A,"fullRestart":full,"pause":false,"reason":"manual"}}]\n`;
    `result.code !== 0` → throw `result.message`. Stop: `app.stop` `{ appId }`, then kill the group
    after 5 s if still alive (kill at once when there is no appId yet).
    `canReload` = flutter, mode `debug`, phase `running`.
- **Check** (needs A; an emulator from **Devices** or a phone; use a copy of a project or a fresh
  `flutter create --org x.y demo` / Android Studio template project in the scratch dir, then add a
  `productFlavors { create("dev") { dimension = "d"; applicationIdSuffix = ".dev" } }` with
  `flavorDimensions += "d"`):
  ```sh
  node -e '
    const r = await import("./src/runner.mjs");
    await r.startRun({ path: process.argv[1], serial: process.argv[2], flutter: { flavor: "dev", mode: "debug", target: null, args: [] } }, "/tmp/mp-check");
    let since = 0;
    for (let i = 0; i < 600; i++) {
      const s = r.runState(since); since = s.next;
      for (const l of s.lines) console.log(l.stream, l.text);
      if (s.job.phase === "running") { await r.reloadRun(false); await r.stopRun(); }
      if (["stopped", "failed"].includes(s.job.phase)) break;
      await new Promise((t) => setTimeout(t, 500));
    }' <flutter project copy> emulator-5554
  ```
  Expect: build lines, phase `running`, the app visible in the pane, a reload with no error, then
  `stopped` and the app gone. Same with `gradle: { installTask: ":app:installDevDebug" }`: the app
  starts, logcat lines appear, Stop force-stops it. With two devices connected, only the given serial
  gets the APK (`adb -s <other> shell pm list packages <appId>` is empty).
- **Depends on:** A (for its check; the code can be written in parallel against the signatures).

### D. Server routes, docs, dist

- **Goal:** wire A and B into the HTTP server and ship it.
- **Changes:** `src/server.mjs`, `README.md`, `CHANGELOG.md`; regenerates `dist/` with

## Risks to watch

- `ANDROID_SERIAL` is how AGP's install task picks one device; B's check confirms it with two
  devices. If it ever installs on all of them, switch to `assemble<Variant>` + `adb -s <serial>
  install -r <apk from output-metadata.json>`.
- AGP < 7 has no `androidComponents`: the variant run fails with a Gradle error, shown as is.
- Gradle's first run on a project can download dependencies (minutes); the UI says so and the
  answer is cached.
- A pinned Flutter version that isn't installed (2 of the 4 flavored Flutter projects here): see
  open question 1.
